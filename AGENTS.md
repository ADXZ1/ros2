# Repository Guidelines

## Project Structure & Module Organization

This repository is a ROS 2 workspace. Make source changes under `chapt7_ws/src/`; root-level `build/`, `install/`, and `log/` directories are generated by `colcon` and should not be edited or committed.

- `fishbot_description/`: FishBot URDF/Xacro models, Gazebo worlds, RViz/controller/SLAM configuration, launch files, and small `rclpy` helper nodes in `scripts/`.
- `fishbot_navigation2/`: Navigation2 launch configuration, parameter files, and saved maps.
- `urdf/fishbot/`: componentized robot model; keep actuator, sensor, and plugin Xacros in their existing subdirectories.

## Build, Test, and Development Commands

Run commands from `chapt7_ws` after sourcing your ROS 2 installation:

```bash
source /opt/ros/jazzy/setup.bash
colcon build --symlink-install
source install/setup.bash
colcon test
colcon test-result --verbose
```

Use `colcon build --packages-select fishbot_description` for a focused rebuild. Launch the simulator with `ros2 launch fishbot_description gazebo_sim.launch.py`; start navigation with `ros2 launch fishbot_navigation2 navigation2.launch.py`. Source `install/setup.bash` again after rebuilding.

## Coding Style & Naming Conventions

Use four spaces in Python and follow PEP 8: `snake_case` for modules, functions, topics, and parameters; `PascalCase` for node classes. Keep launch modules named `*_launch.py` or `*.launch.py` consistently with their package. Use two-space indentation in XML/YAML and preserve readable, component-based Xacro files. CMake enables `-Wall -Wextra -Wpedantic`; resolve new warnings. Do not hand-edit generated copies under any `build/` or `install/` tree.

## Testing Guidelines

Both packages use `ament_lint_auto` and `ament_lint_common` when `BUILD_TESTING` is enabled. Run the full test commands above, or target one package with `colcon test --packages-select fishbot_navigation2`. Add automated tests when introducing executable behavior; name Python tests `test_*.py`. For model or launch changes, also verify that Gazebo starts without errors and inspect the robot, TF tree, sensor topics, and Navigation2 map alignment.

## Commit & Pull Request Guidelines

No repository Git history is available in this checkout. Use short, imperative commit subjects, optionally scoped, such as `description: fix laser frame mapping`. Keep generated artifacts out of commits. Pull requests should describe the behavior changed, list build/test commands run, link related issues, and include screenshots or short recordings for RViz, Gazebo, URDF, or map changes.
